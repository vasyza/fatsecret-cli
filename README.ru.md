# fatsecret-cli

[English](README.md) | Русский

Консольный клиент FatSecret на Rust. Позволяет искать продукты и рецепты, проверять штрихкоды, добавлять записи в дневник питания, записывать вес и просматривать данные аккаунта из терминала.

CLI использует авторизацию и эндпоинты мобильного приложения, а не публичный FatSecret Platform API. Для входа нужен аккаунт FatSecret; регистрировать приложение разработчика или оплачивать подписку Platform API не требуется. Это неофициальный клиент, не связанный с FatSecret и не одобренный компанией. Эндпоинты мобильного приложения могут измениться без предупреждения.

Цель проекта: охватить функциональность мобильного приложения. В версии 0.1.0 полного соответствия пока нет: часть команд только читает данные, некоторые запросы на запись сервер отклоняет, ряд функций приложения отсутствует. Перед использованием ознакомьтесь с разделом [текущие возможности](#текущие-возможности).

## Установка

Для сборки из локальной копии репозитория нужны актуальная стабильная версия Rust и Cargo. При необходимости установите Rust через [rustup](https://rustup.rs/).

```sh
cargo install --path . --locked
fatsecret-cli --version
```

Cargo обычно устанавливает исполняемый файл в `~/.cargo/bin`; этот каталог должен входить в `PATH`. Чтобы собрать программу внутри репозитория:

```sh
cargo build --release --locked
./target/release/fatsecret-cli --help
```

В манифесте указан Rust 1.85, но код использует синтаксис let chains, для которого нужен Rust 1.88 или новее. Заявленный минимум не проверен с зафиксированными зависимостями; используйте актуальную стабильную версию, не рассчитывая на совместимость с 1.85.

Сетевым командам нужен доступ к FatSecret. При первичной регистрации устройства CLI также обращается к Firebase Installations. Для TLS используется rustls. В Unix доступ к файлам учётных данных ограничивается владельцем; на других ОС нужны соответствующие права доступа к файловой системе. Это не означает, что работа проверена на каждой платформе.

## Быстрый старт

Войдите из интерактивного терминала. Вводимый пароль не отображается.

```sh
fatsecret-cli auth login you@example.com
fatsecret-cli auth status
fatsecret-cli foods search "oatmeal"
```

Перед добавлением записи изучите найденный продукт. ID продукта и ID порции различаются; порция должна принадлежать выбранному продукту.

```sh
fatsecret-cli foods get 39715 --format json
fatsecret-cli foods popular 39715 --format json
```

Замените ID из примера значениями из своих результатов. В POSIX-совместимой оболочке при добавлении записи явно укажите местную дату:

```sh
fatsecret-cli diary add \
  --food-id 39715 \
  --serving-id 62446 \
  --meal breakfast \
  --units 1 \
  --date "$(date +%F)" \
  --format json

fatsecret-cli diary day --format json
```

Команда изменяет ваш настоящий аккаунт. Сохраните ответ на добавление, если запись может понадобиться удалить: ответ на запрос дня не всегда содержит ID записей. Проверьте дату и запись в мобильном приложении. Явная дата позволяет обойти текущую ошибку вычисления даты по умолчанию, описанную в разделе [решение проблем](#решение-проблем).

Запишите вес в килограммах:

```sh
fatsecret-cli weight log 75.2 --goal-kg 70
```

Команда обновляет текущий вес и указанную цель. Без `--goal-kg` CLI сохраняет цель аккаунта, если API возвращает её числом. Если значение отсутствует или имеет другой тип, новым целевым весом становится указанный текущий вес.

## Текущие возможности

В таблице разделены наличие команды и результат проверки на реальном сервере. Успешная проверка в прошлом не гарантирует, что закрытый эндпоинт по-прежнему работает для любого аккаунта или рынка.

| Область | Доступные действия | Ограничения и результаты проверок |
| --- | --- | --- |
| Авторизация | Вход, локальные статус/выход, регистрация, восстановление пароля | Вход и отправка письма для сброса пароля проверены на сервере. Регистрация и завершение сброса реализованы, но полная проверка этих сценариев не подтверждена. Входа через социальные сервисы нет. |
| Продукты | Поиск, карточки, популярные порции, типы пищевых предпочтений и голоса, штрихкоды | Поиск, карточки, популярные порции, типы и штрихкоды проверены на сервере. Отправка голосов реализована; это не подтверждает работу каждой пары типа и значения. |
| Рецепты | Поиск, карточки, категории, поиск и подсчёт в кулинарной книге | Поиск, карточки, категории и подсчёт проверены на сервере. Поиск по кулинарной книге реализован без такого же подтверждения. |
| Дневник питания | Чтение текущего дня, добавление, удаление по известному ID | Добавление и удаление проверены на сервере, включая видимость в приложении. Нет надёжного списка ID записей, просмотра прошлых дней, месяца или копирования. Есть ограничения по датам. |
| Вес | Запись текущего и целевого веса | Сервер принял запись при проверке. Истории и выбора даты нет. |
| Упражнения | Текущий день, типы активности, запись активности | Чтение проверено на сервере. Запись сервер отклонил. |
| Вода | Чтение текущего дня и запись выпитой воды | Только для Premium: аккаунт из проверок — `registered non-premium`, сервер отклоняет обе операции (299 `Could not save`). |
| Сохранённые приёмы пищи | Список, карточки, быстрый выбор, изменение приёмов пищи и продуктов, добавление в дневник | Чтение проверено на сервере. Создание/удаление проверены вживую через form-POST (транспорт приложения); остальные записи используют тот же транспорт, но не проверены. |
| Аккаунт и настройки | Данные, настройки аккаунта, смена имени, атрибуты, локаль | Чтение проверено на сервере. Смена имени реализована и при успешном ответе сразу изменяет аккаунт. Общего редактирования настроек нет. |
| Уведомления | Список | Только чтение; проверено на сервере. |
| Социальные функции | Списки пользователей, связанные с блокировками | Только чтение; проверено на пустых списках. Справка описывает `blocks` как заблокировавших вас, а `blocking` как заблокированных вами; направление не проверено на заполненных списках. Нет публикаций в ленте и команд блокировки/разблокировки. |
| Обучение | Материалы, прогресс, закладки в ответе с прогрессом | Чтение проверено на сервере. Нет записи прогресса уроков или закладок. |
| Группы продуктов | Статические данные групп | Проверено на сервере; вход всё равно обязателен. |

Не реализованы: управление избранным, создание собственных продуктов и работа с их изображениями, вход через социальные сервисы, AI/распознавание изображений, обновление игровых показателей и серий активности, полное соответствие мобильному приложению. Наличие команды в `--help` подтверждает её существование, а не работоспособность серверного сценария.

## Справочник команд

```text
fatsecret-cli [OPTIONS] <COMMAND>
fatsecret-cli <COMMAND> --help
fatsecret-cli <COMMAND> <SUBCOMMAND> --help
```

В таблицах слова в верхнем регистре обозначают ваши значения, квадратные скобки обозначают необязательные аргументы. Сами скобки вводить не нужно. Команды и флаги одинаковы для обеих языковых версий README.

Все команды работы с данными требуют сохранённых или переданных через окружение учётных данных, включая поиск продуктов и группы продуктов. Справка и автодополнение не требуют входа. Команды авторизации сами выполняют локальные действия или запросы до входа.

### Глобальные параметры

| Параметр | Значение |
| --- | --- |
| `-c, --config PATH` | Выбрать TOML-файл конфигурации. Также задаётся через `FATSECRET_CONFIG`. |
| `--format human\|json\|plain` | Формат вывода; по умолчанию `human`. Авторизация и автодополнение являются исключениями. |
| `--color auto\|always\|never` | Цвет логов только в stderr; данные остаются без цвета. По умолчанию `auto`. |
| `-v, --verbose` | Если `RUST_LOG` не задан: `-v` это `info`, `-vv` это `debug`, без флага `warn`. Заданный `RUST_LOG` имеет приоритет. |
| `-h, --help` | Показать справку. |
| `-V, --version` | Показать версию. |

Глобальные параметры можно указывать после подкоманд. Заданный `RUST_LOG` перекрывает `-v`.

### Авторизация

| Команда | Поведение |
| --- | --- |
| `auth login USERNAME` | Принимает имя пользователя или email, запрашивает пароль и сохраняет учётные данные. |
| `auth register EMAIL USERNAME --birth-date YYYY-MM-DD --gender GENDER [--country US]` | Создаёт аккаунт; запрашивает пароль. Пол передаётся как введён, например `Male` или `Female`. |
| `auth forgot-password EMAIL` | Отправляет письмо для сброса пароля. |
| `auth reset-password` | Запрашивает код сброса и новый пароль. После этого нужно войти заново. |
| `auth status` | Проверяет локальные учётные данные или окружение, а не их действительность на сервере. Возвращает ошибку, если вход не выполнен. |
| `auth logout` | Удаляет выбранный файл учётных данных. Не отзывает их на сервере и не очищает переменные окружения. |

Регистрация также принимает `--current-weight-kg NUMBER`, `--goal-weight-kg NUMBER`, `--height-cm NUMBER` и `--first-name TEXT`. Страна по умолчанию `US`. Регистрация не выполняет автоматический вход; пройдите необходимые шаги подтверждения аккаунта и затем запустите `auth login`.

Флага пароля, переменной окружения для пароля и чтения пароля из stdin нет. Запускайте запросы пароля в обычном терминале. Вход по токенам социальных провайдеров не поддерживается.

### Продукты

| Команда | Поведение и значения по умолчанию |
| --- | --- |
| `foods search QUERY [--page 0] [--size 20] [--market CODE] [--lang CODE]` | Поиск продуктов. Нумерация страниц с нуля. Запрос из нескольких слов заключайте в кавычки. Индекс маркета определяет выдачу (`RU` находит русские продукты; по умолчанию `US` из настроек, переопределение через `FATSECRET_MARKET_LOCALE`). |
| `foods get ID` | Карточка продукта с порциями, если сервер их возвращает. |
| `foods popular ID [ID ...]` | Популярные порции. Используйте `--format json`; вывод plain пустой. |
| `foods barcode GTIN` | Поиск по цифрам штрихкода, затем получение карточки найденного продукта. Сохраняйте ведущие нули. |
| `foods preference-types` | Типы пищевых предпочтений и аллергенов. |
| `foods vote-preference ID --vote TYPE=VALUE [--vote TYPE=VALUE ...]` | Отправка голосов. `TYPE` должен быть числом; значения уходят на сервер строками. |

Получайте типы через `foods preference-types`; не предполагайте, что значения должны быть логическими или числовыми. Если ответ по штрихкоду не содержит распознанного ID продукта, plain-режим выводит `NOT_FOUND`, но код завершения остаётся успешным. JSON содержит карточку найденного продукта либо ответ сканирования, если совпадение не распознано.

### Рецепты

| Команда | Поведение и значения по умолчанию |
| --- | --- |
| `recipes search QUERY [--page 0]` | Поиск по старому индексу рецептов. |
| `recipes get ID` | Карточка рецепта через тот же эндпоинт, что используется для продуктов. |
| `recipes categories` | Список категорий рецептов. |
| `recipes cookbook-search QUERY [--page 0] [--size 20]` | Поиск по индексу кулинарной книги. |
| `recipes cookbook-count [--market US]` | Количество рецептов для рынка, например `US`. |

Нумерация страниц начинается с нуля. `--market` относится только к подсчёту рецептов, а не к общему выбору языка поиска.

### Дневник питания

| Команда | Поведение и значения по умолчанию |
| --- | --- |
| `diary day [--date YYYY-MM-DD]` | Чтение записей любого дня с ID, БЖУ, порциями и итогами дня. История работает (та же страница + выбор дня). |
| `diary add --food-id ID --serving-id ID [--meal other] [--meal-id ID] [--date YYYY-MM-DD] [--units 1]` | Добавление продукта с выбранной порцией. Лучше указывать дату явно. |
| `diary rm ENTRY_ID [--date YYYY-MM-DD]` | Удаление по ID из вывода `diary day`. `--date` это записанная дата (по умолчанию сегодня). Без подтверждения. |
| `diary cp --from YYYY-MM-DD [--date YYYY-MM-DD]` | Копирование записей дня на другую дату (те же приёмы пищи, новые ID). |

`--units` задаёт множитель порции, а не граммы. Чтобы указать массу, выберите порцию, измеряемую в граммах. Регистр названий приёмов пищи не важен:

| Приём пищи | ID на сервере |
| --- | --- |
| `other` | 0 |
| `breakfast` | 1 |
| `lunch` | 2 |
| `dinner` | 3 |
| `snack` | 4 |
| `prebreakfast` или `pre-breakfast` | 5 |
| `secondbreakfast` или `second-breakfast` | 6 |

`--meal-id` имеет приоритет над названием. ID продукта, ID порции и ID записи дневника не взаимозаменяемы. `diary day` показывает строки записей с их ID, группируя по приёмам пищи с итогами энергии.

### Вес, упражнения и вода

| Команда | Поведение и значения по умолчанию |
| --- | --- |
| `weight log KG [--goal-kg KG]` | Запись веса в килограммах; поведение целевого веса описано в быстром старте. |
| `exercise day` | Чтение текущего дня активности. |
| `exercise types` | Список ID типов активности. |
| `exercise log --type-id ID --mins MINUTES [--kcal NUMBER] [--description TEXT]` | Отправка длительности, необязательного расхода энергии и заметки. Без `--kcal` расчёт остаётся на стороне сервера. Известен отказ сервера. |
| `water day` | Чтение воды за текущий день. Требуется Premium; без него — 299 `Could not save`. |
| `water log ML [--goal-ml 2000]` | Отправка добавочного объёма воды в миллилитрах и дневной цели. Требуется Premium; без него — 299 `Could not save`. |

У этих команд нет выбора даты. Для воды используется календарный день UTC. Не повторяйте запись только потому, что текстовый вывод оказался кратким; сначала проверьте состояние аккаунта.

### Сохранённые приёмы пищи

Это наборы продуктов для повторного использования, а не категории завтрака, обеда или ужина в дневнике. Записи идут form-POST-запросами, как в приложении; создание/удаление проверены вживую полным циклом.

| Команда | Поведение и значения по умолчанию |
| --- | --- |
| `meals ls [--meal 0]` | Список сохранённых приёмов пищи с фильтром по числовому порядковому номеру вкладки. |
| `meals show ID` | Приём пищи и его продукты. |
| `meals quickpicks` | Чтение списка быстрого выбора. |
| `meals create --title TEXT [--description TEXT] [--meal-types 1]` | Создание приёма пищи. Описание по умолчанию пустое. |
| `meals save ID --title TEXT [--description TEXT] [--meal-types 1]` | Сохранение метаданных. Если описание и типы не указаны, используются значения по умолчанию, а не прежние значения. |
| `meals rm ID` | Удаление приёма пищи. |
| `meals log ID [--meal other] [--meal-id ID]` | Добавление сохранённого приёма пищи в дневник; используется таблица названий выше. |
| `meals add-item --meal-id ID --food-id ID --name TEXT --portion-id ID [--units 1] [--item-id 0]` | Добавление продукта; существующий `--item-id` включает редактирование. |
| `meals rm-item ITEM_ID` | Удаление продукта из сохранённого приёма пищи. |

`meals ls --meal` обозначает порядковый номер вкладки, `--meal-types` является строковой маской сервера, а `meals add-item --meal-id` указывает на сохранённый приём пищи. Эти значения не взаимозаменяемы с ID категории приёма пищи в дневнике.

## Вывод и скрипты

Команды работы с данными выводят результат в stdout. Ошибки и диагностика tracing идут в stderr. Успешный вызов завершается с кодом `0`; ошибки выполнения дают ненулевой код, неверные аргументы обычно дают код `2`.

- `human` используется по умолчанию: таблицы, сводки или подсказка посмотреть JSON.
- `json` выводит разобранный ответ API как форматированный JSON. Старые XML-ответы преобразуются в JSON; текстовые узлы могут выглядеть как `{"$text":"..."}`, а одиночные объекты превращаться в массивы при повторении. Пустой успешный ответ может быть `null`.
- `plain` выводит данные конкретной команды, обычно с разделением табуляцией, без общей схемы. Команды записи часто печатают `OK`. У некоторых команд содержательного plain-представления нет.

Команды авторизации учитывают `--format` (текст `human`/`plain` или JSON со статусом). Автодополнение всегда выводит код оболочки. JSON отражает ответы сервера, а не версионируемую схему CLI; учитывайте отсутствующие поля и различия структуры между эндпоинтами.

Пример с установленным [jq](https://jqlang.org/):

```sh
fatsecret-cli foods search "oatmeal" --format json \
  | jq '.recipes[]? | {id, title}'

fatsecret-cli foods search "oatmeal" --format plain
fatsecret-cli learning progress --format json
```

В скриптах Bash и Zsh включайте `set -o pipefail`, чтобы следующая команда конвейера не скрыла ошибку CLI. Случай `NOT_FOUND` для штрихкода является исключением: код `0` не означает найденный продукт. Успешный ответ на запись также не доказывает, что она появилась на нужную дату; проверьте её в приложении.

## Конфигурация

Для обычной работы файл конфигурации не нужен. Значения разрешаются в таком порядке:

1. Переопределения из переменных окружения `FATSECRET_*`.
2. Выбранный TOML-файл.
3. Встроенные значения по умолчанию.

Выбор файла происходит отдельно: сначала `--config PATH`, затем `FATSECRET_CONFIG`, затем стандартный путь платформы. Отсутствие файла по умолчанию допустимо; отсутствие явно выбранного файла является ошибкой.

Стандартный каталог содержит `config.toml`, `credentials.json` и `device.json`:

| Платформа | Каталог по умолчанию |
| --- | --- |
| macOS | `~/Library/Application Support/fatsecret-cli/` |
| Linux | `$XDG_CONFIG_HOME/fatsecret-cli/` либо `~/.config/fatsecret-cli/`, если переменная не задана |
| Windows | Каталог перемещаемых данных приложений пользователя, обычно `%APPDATA%\fatsecret-cli\` |

Минимальная необязательная конфигурация:

```toml
device_model = "android"
app_version = "11.8.0.5"
```

```sh
fatsecret-cli --config ./config.toml foods search "oatmeal"
```

Для каждого поддерживаемого ключа TOML есть переменная окружения:

| Ключ TOML | Переменная окружения | Назначение |
| --- | --- | --- |
| `device_model` | `FATSECRET_DEVICE_MODEL` | Строка модели устройства; не должна быть пустой. |
| `app_version` | `FATSECRET_APP_VERSION` | Версия мобильного приложения в заголовках. |
| `device_id` | `FATSECRET_DEVICE_ID` | Переопределение идентификатора установки. Обычно не нужно. |
| `auth_url` | `FATSECRET_AUTH_URL` | Вход. |
| `food_search_url` | `FATSECRET_FOOD_SEARCH_URL` | Поиск продуктов. |
| `food_popular_url` | `FATSECRET_FOOD_POPULAR_URL` | Популярные порции. |
| `food_vote_url` | `FATSECRET_FOOD_VOTE_URL` | Голоса о пищевых предпочтениях. |
| `food_types_url` | `FATSECRET_FOOD_TYPES_URL` | Типы пищевых предпочтений. |
| `recipe_count_url` | `FATSECRET_RECIPE_COUNT_URL` | Подсчёт рецептов кулинарной книги. |
| `scan_url` | `FATSECRET_SCAN_URL` | Сканирование штрихкода. |

| `reset_url` | `FATSECRET_RESET_URL` | Завершение сброса пароля. |

| `change_username_url` | `FATSECRET_CHANGE_USERNAME_URL` | Смена имени аккаунта. |

| `learning_course_bookmark_save_url` | `FATSECRET_LEARNING_COURSE_BOOKMARK_SAVE_URL` | Сохранение закладки курса. |
| `learning_course_bookmark_delete_url` | `FATSECRET_LEARNING_COURSE_BOOKMARK_DELETE_URL` | Удаление закладки курса. |

Управляйте файлом без ручного редактирования TOML:

```sh
fatsecret-cli config show
fatsecret-cli config set market_locale RU
fatsecret-cli config unset market_locale
fatsecret-cli config path
```

`config show` скрывает идентификатор устройства. Значения из `config set`
сильнее встроенных, но слабее переменных `FATSECRET_*`.

Современные эндпоинты по умолчанию находятся на `https://app.ftscrt.com/`; база старых: `https://android.fatsecret.com/android/`. Атрибуты, чтения списков блокировок и чтения обучения используют фиксированные современные URL без переопределения. Изменение `server_base` не перенаправляет все запросы.

Изменение `--config` не переносит учётные данные и идентификатор устройства и не выбирает отдельный профиль аккаунта.

## Учётные данные и конфиденциальность

CLI сохраняет выданные сервером учётные данные в `credentials.json`, а не ваш пароль. Файл не зашифрован и не хранится в системной связке ключей. В Unix при записи выставляются права `0600`; любой, кто может прочитать файл, получит его учётные данные. Защитите каталог, резервные копии и системную учётную запись. В Windows самостоятельно настройте подходящие ACL.

Для автоматизации следующие переменные окружения заменяют загрузку из файла, если присутствуют все три обязательных значения:

| Переменная | Назначение |
| --- | --- |
| `FATSECRET_SERVER_ID` | Числовой ID аккаунта на сервере. |
| `FATSECRET_SECRET_KEY` | Секретный ключ аккаунта. |
| `FATSECRET_DEVICE_KEY` | Выданный сервером ключ устройства. |
| `FATSECRET_USERNAME` | Необязательное имя для `auth status` при учётных данных из окружения. |
| `FATSECRET_CREDENTIALS` | Переопределение пути файла для чтения, сохранения и выхода. |

Если тройка переменных неполная, CLI читает файл; объединения отдельных полей нет. Передавайте секреты через защищённое хранилище системы автоматизации, а не через команды, попадающие в историю оболочки. Встроенной команды экспорта учётных данных нет. Не коммитьте файлы учётных данных или открытые `.env` и не прикладывайте их содержимое к сообщениям об ошибках.

`device.json` хранит отдельный идентификатор установки Firebase. При входе, регистрации и восстановлении пароля CLI сначала использует явно заданный идентификатор, затем сохранённый, а при их отсутствии регистрирует новый в Firebase. `FATSECRET_DEVICE_ID` и `FATSECRET_DEVICE_KEY` обозначают разные вещи.

`auth logout` удаляет только выбранный файл учётных данных. `device.json`, конфигурация и учётные данные в окружении остаются. Чтобы перестать использовать переменные с учётными данными, очистите их в родительской оболочке или окружении автоматизации. Удаление локального файла не отзывает данные на сервере.

Вывод аккаунта, дневника, уведомлений и обучения может содержать персональные данные. Проверяйте JSON и диагностику перед публикацией. Режима dry-run и общего запроса подтверждения для записи или удаления нет.

## Автодополнение

Поддерживаются Bash, Elvish, Fish, PowerShell и Zsh.

```sh
fatsecret-cli completions bash
fatsecret-cli completions elvish
fatsecret-cli completions fish
fatsecret-cli completions powershell
fatsecret-cli completions zsh
```

Каждая команда выводит скрипт автодополнения в stdout без обращения к аккаунту. Для текущей сессии Bash:

```bash
source <(fatsecret-cli completions bash)
```

Для Fish сохраните его в пользовательский каталог автодополнения:

```fish
mkdir -p ~/.config/fish/completions
fatsecret-cli completions fish > ~/.config/fish/completions/fatsecret-cli.fish
```

Для Zsh поместите сгенерированный файл `_fatsecret-cli` в каталог из `fpath` и инициализируйте автодополнение через `compinit`. Для постоянной загрузки используйте обычную настройку файлов запуска вашей оболочки.

## Решение проблем

### Исполняемый файл не найден

Добавьте каталог исполняемых файлов Cargo в `PATH` либо используйте `./target/release/fatsecret-cli` после release-сборки. Отладочная сборка находится в `./target/debug/fatsecret-cli`.

### Запрос пароля не работает в конвейере или CI

Нужен интерактивный терминал; без него возможна ошибка `Device not configured`. Не передавайте пароль через конвейер или аргумент. Войдите интерактивно либо передайте выданную сервером тройку учётных данных через защищённое хранилище автоматизации.

### Вход не выполнен или сервер отклоняет учётные данные

`auth status` проверяет локальную загрузку данных и не обращается к FatSecret. Если сервер их отклоняет, выполните `auth login` заново. Переменные окружения с учётными данными имеют приоритет даже над только что записанным файлом. Проверяйте наличие переменных, не выводя секретные значения.

### При входе возвращается тип ошибки 299

В прошлых проверках причиной этой общей ошибки был отсутствующий идентификатор установки. Теперь клиент создаёт его автоматически. Проверьте доступ к Firebase и явное переопределение `FATSECRET_DEVICE_ID`. Сама ошибка не доказывает, что текущая причина связана именно с идентификатором устройства.

### Неверная дата дневника или отсутствующие ID записей

Даты дневника по умолчанию это текущий календарный день UTC (число суток от начала эпохи, округлённое вниз). Это совпадает с `recordedDate`/`dateInt`. Местный часовой пояс не используется. Для конкретной даты укажите `--date YYYY-MM-DD` в `diary add` и `diary rm`.
`diary day` читает любой день на сервере: укажите `--date YYYY-MM-DD` для истории (та же страница + выбор дня). Страница читается form-POST-запросом, как в приложении; GET возвращает только оболочку `{dateint, guid}`.

Разбор даты отклоняет невозможные календарные даты (включая 29 февраля невисокосного года), но терпим к дополнению нулями и лишним сегментам. Указывайте настоящую дату `YYYY-MM-DD`.

### `Unable to save` или отказ с пустым ответом

Для записи сохранённых приёмов пищи, упражнений и операций с водой известны отказы сервера. Старые эндпоинты могут вернуть HTTP 200 с текстом `Unable to save`; CLI считает это ошибкой. Успешный HTTP-код сам по себе не подтверждает сохранение. Не повторяйте изменяющие запросы, не проверив состояние аккаунта.

### Пропущенные поля, странные единицы или неполные таблицы

Посмотрите разобранный ответ через `--format json`. Структура старого XML отличается от современного JSON, а текстовые представления показывают только часть полей. Запросы отправляют `unit: kj`, но живые значения продуктов могут совпадать с килокалориями (у овса `energyPerPortion` 389 на 100 г). Таблицы подписывают число как `energy` и не пересчитывают его. Перед интерпретацией значений проверьте исходное поле и мобильное приложение.

Глобального флага выбора локали или единиц нет. `settings locale` только читает настройки. Не считайте, что все поисковые запросы используют рынок из `recipes cookbook-count`.

### Логирование

Если `RUST_LOG` не задан, `-v` и `-vv` включают уровни `info` и `debug`. `--color never` отключает ANSI в stderr. Избегайте общего debug/trace-логирования при работе с учётными и персональными данными; перед публикацией удаляйте их из диагностики.

## Разработка

```sh
cargo build --locked
cargo test --locked
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
```

Тесты проверяют локальное поведение и справку CLI; их успешное прохождение не подтверждает совместимость с удалёнными эндпоинтами. Для реальных записей используйте тестовый аккаунт и проверяйте результат в FatSecret. Не добавляйте настоящие секреты в фикстуры.

| Путь | Назначение |
| --- | --- |
| `src/cli.rs` | Команды, флаги и справка. |
| `src/commands/` | Диспетчеризация и сценарии команд. |
| `src/api/client.rs` | Запросы, обработка эндпоинтов, разбор JSON/XML. |
| `src/auth/` | Вход, хранение учётных данных, идентификатор установки. |
| `src/config.rs` | TOML, переопределения окружения, значения по умолчанию. |
| `src/output.rs` | Вывод human, plain и JSON. |
| `src/main.rs` | Запуск CLI, tracing, автодополнение, ошибки. |
| `tests/cli_help.rs` | Проверки справки и доступа без авторизации. |

При изменении команды обновляйте справку и обе версии README. В сообщение об ошибке включайте версию CLI, ОС, команду без чувствительных аргументов, код завершения и очищенную от личных данных ошибку или ответ. Укажите, работает ли то же действие в мобильном приложении. Не прикладывайте пароли, файлы учётных данных, секретные заголовки или приватные данные аккаунта.
